# CJM (AS-IS) — открытие нового брокерского счёта (шаблон)

Этот шаблон предназначен для фиксации **фактического** пути клиента при открытии нового счёта в ЛК/приложении.
Заполняется по результатам прохождения сценария (видео/скринкаст) + сетевых логов (HAR) + наблюдений.

## Контекст исследования

- **Контур**: тест / прод
- **Канал**: web / iOS / Android
- **Сегмент клиента**:
  - резидент / нерезидент
  - гражданство / налоговое резидентство
  - новый клиент / уже клиент (есть договор) / есть учётка
  - возраст 18+ / 14–17 (если применимо)
- **Тип счёта**: брокерский / ИИС / маржинальный / валюта / иной
- **Целевое действие (first value)**: “счёт открыт” / “счёт открыт + можно пополнить” / “первая сделка”
- **Допущения и ограничения**:
  - необходимость 2FA
  - какие документы доступны (паспорт/ID)
  - доступные способы подписи (SMS/простая ЭП/КЭП)
  - ограничения по устройству (камера/браузер)

## Карта пути (CJM)

### Легенда полей на шаг

- **Цель пользователя**: что пытается сделать
- **Точка контакта**: экран/страница/пуш/смс
- **Действия**: что делает пользователь
- **Системные события**: что делает система (запросы/проверки/статусы)
- **Артефакты**: что пользователь видит/подписывает/загружает
- **Боли/фейлы**: где и почему ломается
- **Эмоции**: коротко (😊/😐/😟 — опционально)
- **Метрика шага**: время, ошибки, конверсия, SLA
- **Улучшение (to-be)**: кратко

---

### Шаг 0. Триггер / мотивация

- **Контекст**: почему пришёл (реклама/совет/перевод активов/нужна конкретная бумага/льготы ИИС)
- **Ожидание**: “открою за ___ минут, нужны ___ документы”
- **Риски непопадания**: непонятно какой счёт, требования раскрываются поздно

### Шаг 1. Точка входа и выбор сценария

- **Точка контакта**: лендинг/ЛК/приложение
- **Варианты**: “уже клиент” / “новый” / “восстановить”
- **Боли**: неверная ветка, нет ясного “что дальше”, нет оценочного времени

### Шаг 2. Аутентификация / регистрация

- **Действия**: телефон/email → код → пароль/пин
- **Системные события**: отправка OTP, rate limit, проверка дублей
- **Боли**:
  - код не приходит / задержка
  - нельзя продолжить без повторной регистрации
  - непонятные правила пароля

### Шаг 3. Выбор продукта/счёта/тарифа

- **Действия**: выбрать тип счёта, тариф, доп. опции
- **Боли**:
  - сравнение тарифов без калькулятора
  - условия спрятаны в PDF
  - непонятно “что оптимально мне”

### Шаг 4. Анкета KYC/AML (профиль клиента)

- **Данные**: ФИО/дата/паспорт/адрес/ИНН/СНИЛС/занятость/доход/опыт/цели
- **Системные события**: валидации, подсказки, автозаполнение, черновик
- **Боли**:
  - слишком много полей “сразу”
  - ошибки появляются только на финале
  - формулировки непонятны (примеров нет)

### Шаг 5. Документы / селфи / подтверждение личности

- **Действия**: фото/скан документа, селфи/видео, повторные попытки
- **Системные события**: проверка качества, OCR, антифрод
- **Боли**:
  - нет чеклиста “как правильно”
  - частые отклонения без конкретной причины
  - зависимость от камеры/разрешений

### Шаг 6. Согласия / раскрытия / договоры

- **Артефакты**: договор, регламент, риски, ПДн, FATCA/CRS (если есть)
- **Боли**:
  - слишком длинные тексты без краткого summary
  - непонятно что обязательно, что опционально
  - “галочки” без доверия

### Шаг 7. Подписание

- **Способ**: SMS/простая ЭП/КЭП/другое
- **Боли**:
  - неочевидный переход в отдельный сервис
  - подпись недоступна для части пользователей
  - сбой подписи без пути восстановления

### Шаг 8. Проверка / ожидание (если есть)

- **Статусы**: “отправлено” → “на проверке” → “нужны данные” → “одобрено/отказ”
- **SLA**: заявленное ___, фактическое ___
- **Боли**:
  - неясно сколько ждать
  - нет уведомлений/трекера
  - причины “нужны данные/отказ” непрозрачны

### Шаг 9. Результат и first value

- **Результат**: счёт открыт (номер/реквизиты), доступность торговли/пополнения
- **Next best action**: пополнить, пройти тест, выбрать тариф, подключить 2FA и т.д.
- **Боли**:
  - “счёт открыт, но нельзя ___” без объяснения
  - нет понятного “что делать дальше”
