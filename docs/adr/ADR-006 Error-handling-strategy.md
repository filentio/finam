# ADR-006 Error-handling-strategy

## Title
Стратегия обработки ошибок и маппинг кодов HH (401/403/429/5xx)

## Status
Accepted

## Context
Интеграция с HH API приводит к ошибкам разных классов:
- 401/invalid token: истёк токен, нужен refresh или переавторизация;
- 403: недостаточно прав, запреты, возможные ограничения аккаунта;
- 429: превышение лимитов/rate limit;
- 5xx/timeouts: временная недоступность или сетевые проблемы;
- бизнес-ошибки: “нельзя отправить отклик на эту вакансию”, “вакансия закрыта”, “резюме недоступно”.

Нужно единообразно:
- показывать понятные сообщения в UI;
- выбирать ретраи только там, где это корректно;
- сохранять причины в истории откликов без PII.

## Decision
- Вводим классификацию ошибок на уровне HH Connector и Apply Orchestrator:
  1) **Auth errors** (401):
     - попытка refresh (если применимо);
     - при неуспехе — статус “нужна повторная авторизация” и блокировка отправки до HH OAuth.
  2) **Permission/forbidden** (403):
     - не ретраить автоматически;
     - переводить отклик в `failed` с понятным `error_code` и инструкцией в UI.
  3) **Rate limit** (429):
     - ретраи с backoff и джиттером в воркере;
     - удержание статуса `queued` до исчерпания политики ретраев;
     - алерт в observability при росте 429.
  4) **Transient** (5xx/timeouts):
     - ретраи с backoff и лимитом попыток;
     - при исчерпании — `failed` с техническим `error_code`.
  5) **Business errors** (4xx доменные):
     - не ретраить;
     - возвращать код ошибки в UI (например, “вакансия не поддерживает отклик через API”).
- В API возвращаем стабильные `error_code` (см. `docs/api_contract.md`) и не пробрасываем “сырые” тексты/структуры, содержащие PII или токены.

## Consequences
Плюсы:
- предсказуемое поведение UI и фоновых задач;
- корректные ретраи без дублей и без “вечных” попыток;
- унификация метрик и алертов по error_code.

Минусы/ограничения:
- требуется поддерживать таблицу соответствия HH ошибок → наши error_code;
- часть ошибок (например, капча/антибот) может требовать ручного вмешательства пользователя и не автоматизируется в MVP.
