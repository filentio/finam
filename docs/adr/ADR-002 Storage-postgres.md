# ADR-002 Storage-postgres

## Title
Основная БД — Postgres

## Status
Accepted

## Context
MVP требует надёжного хранения:
- пользователей и связи с HH аккаунтом (OAuth токены);
- профилей поиска, стоп-листов;
- вакансий (нормализованные поля + ограниченный raw_json);
- матчей/скоринга (score + reasons);
- черновиков письма (версии/правки);
- откликов и статусов;
- аудита действий (одобрение/отправка);
- идемпотентности отправки (Idempotency-Key + результат).

Требования к данным:
- транзакционность (особенно для антидублей и идемпотентности);
- индексы/уникальные ограничения;
- JSON-поля для гибких фильтров и “reasons”;
- возможность шифрования чувствительных полей на уровне приложения.

## Decision
- В качестве основной БД выбираем **Postgres**.
- Все сущности MVP живут в Postgres: `users`, `hh_accounts`, `search_profiles`, `vacancies`, `matches`, `cover_letters`, `applications`, `audit_log`, `idempotency_keys` (или эквивалент).
- JSON-структуры храним как `jsonb` (filters_json, stoplist_json, raw_json, reasons_json), но дублируем ключевые поля в нормализованных колонках для индексации.

## Consequences
Плюсы:
- сильные гарантии транзакций (ACID), удобная реализация уникальностей (антидубли);
- `jsonb` покрывает “гибкие” поля без усложнения схемы;
- зрелая экосистема и наблюдаемость.

Минусы/ограничения:
- требуется дисциплина в хранении raw_json (объём/retention);
- для очередей/кэша может понадобиться дополнительный компонент или паттерн (см. ADR-003).
