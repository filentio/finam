# ADR-004 Human-in-the-loop

## Title
Отправка отклика только после одобрения (approve_and_send)

## Status
Accepted

## Context
Требования этапа 1 фиксируют, что в MVP:
- режим работы — **approve_and_send**;
- отправка отклика должна происходить **только после одобрения** пользователем;
- нужно минимизировать автоматизацию (ToS awareness) и снизить риск банов/репутационных проблем.

Также генерация черновика письма не гарантирует 100% корректность и должна быть проверяема человеком.

## Decision
- Вводим явный шаг **одобрение** перед отправкой:
  - до одобрения отклик существует в статусе `draft` и может редактироваться (черновик письма);
  - одобрение переводит отклик в `approved` и фиксируется в `audit_log`;
  - отправка доступна только из `approved` (с доп. проверками лимитов/quiet hours/антидублей).
- API “send” запрещён для не одобренных откликов.
- UI обязателен: предпросмотр и возможность редактирования черновика письма перед одобрением.

## Consequences
Плюсы:
- снижение риска нежелательных/ошибочных отправок;
- соответствие требованиям MVP и ToS awareness;
- удобный аудит: кто и когда одобрил.

Минусы/ограничения:
- пользовательский шаг добавляет трение (намеренно, в рамках MVP);
- будущий режим `auto_send` потребует отдельного ADR/политики и не входит в MVP.
