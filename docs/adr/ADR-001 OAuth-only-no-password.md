# ADR-001 OAuth-only-no-password

## Title
OAuth HH only: не используем и не храним пароль

## Status
Accepted

## Context
MVP сервиса должен уметь:
- искать вакансии на hh.ru;
- генерировать черновик письма;
- отправлять отклик на hh.ru.

При этом требования этапа 1 фиксируют:
- авторизация и отправка откликов должны работать через **HH OAuth**;
- сервис **не должен** запрашивать или хранить логин/пароль пользователя HH;
- отправка отклика — только после одобрения (human-in-the-loop).

Хранение паролей или попытки “обхода” OAuth повышают риск компрометации, нарушают базовые ожидания безопасности и потенциально противоречат требованиям/политикам hh.ru.

## Decision
- Используем **только HH OAuth** для операций, требующих действий “от имени пользователя” (получение данных аккаунта/резюме, отправка отклика).
- Логин/пароль HH **не собираем**, **не передаём** и **не храним**.
- Токены OAuth (access/refresh, если применимо) храним **в зашифрованном виде**, не логируем, управляем сроками и ре-авторизацией.

## Consequences
Плюсы:
- снижение риска утечки учётных данных;
- соответствие требованиям этапа 1;
- упрощение комплаенса и аудитируемости.

Минусы/ограничения:
- требуется реализация корректного OAuth flow (state/PKCE при необходимости);
- при истечении/отзыве токенов пользователю нужно повторно пройти OAuth.
