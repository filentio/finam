# Acceptance Criteria — MVP (Given / When / Then)

## Поиск и ранжирование
1. **Создание профиля поиска**
   - Given пользователь авторизован через HH OAuth  
   - When пользователь создаёт профиль поиска и сохраняет его  
   - Then профиль поиска появляется в списке профилей и доступен для повторного запуска

2. **Запуск поиска по профилю поиска**
   - Given пользователь выбрал существующий профиль поиска  
   - When пользователь запускает поиск  
   - Then сервис получает вакансии через HH API и показывает список вакансий

3. **Ранжирование вакансий**
   - Given сервис получил список вакансий по профилю поиска  
   - When пользователь открывает список результатов  
   - Then вакансии отсортированы по убыванию ранга и для каждой вакансии отображается краткое объяснение ранга (минимум 1–3 фактора)

4. **Стоп-лист компаний**
   - Given в профиле поиска указан стоп-лист компаний  
   - When пользователь запускает поиск  
   - Then вакансии от компаний из стоп-листа не отображаются в результатах

5. **Стоп-лист ключевых слов**
   - Given в профиле поиска указан стоп-лист ключевых слов  
   - When пользователь запускает поиск  
   - Then вакансии, содержащие стоп-слова в названии или описании (если описание доступно через API), исключаются из результатов

## Черновик письма и UX
6. **Генерация черновика письма**
   - Given пользователь открыл вакансию и выбрал резюме  
   - When пользователь нажимает “Сгенерировать черновик письма”  
   - Then сервис создаёт черновик письма, привязанный к этой вакансии и этому резюме, и показывает его пользователю

7. **Редактирование черновика письма**
   - Given у пользователя открыт черновик письма  
   - When пользователь вносит правки и сохраняет  
   - Then изменения сохраняются и отображаются при повторном открытии черновика письма

8. **Предпросмотр перед отправкой**
   - Given черновик письма создан или отредактирован  
   - When пользователь инициирует одобрение  
   - Then пользователь видит предпросмотр текста черновика письма и понимает, что будет отправлено в отклике

## Одобрение и отправка отклика (approve_and_send)
9. **Отправка только после одобрения**
   - Given пользователь находится на экране вакансии с черновиком письма  
   - When пользователь не выполнял одобрение  
   - Then сервис не отправляет отклик и не вызывает HH API для отправки отклика

10. **Успешная отправка отклика после одобрения**
   - Given пользователь выполнил одобрение  
   - When сервис отправляет отклик через HH API  
   - Then в истории откликов появляется запись со статусом `sent` и привязкой к вакансии и резюме

11. **Обработка ошибки отправки**
   - Given пользователь выполнил одобрение  
   - When HH API возвращает ошибку отправки отклика  
   - Then запись в истории откликов получает статус `failed` и отображается причина ошибки в пользовательском виде (без PII и без токенов)

12. **Quiet hours блокируют отправку**
   - Given включены quiet hours и текущее время попадает в quiet hours  
   - When пользователь выполняет одобрение и пытается отправить отклик  
   - Then сервис не отправляет отклик, сохраняет статус `approved` и предлагает отправить позже

13. **Лимит отправок**
   - Given у пользователя достигнут дневной лимит откликов  
   - When пользователь пытается отправить очередной отклик после одобрения  
   - Then сервис не отправляет отклик, показывает сообщение о лимите и фиксирует попытку без вызова HH API отправки

## Антидубли и идемпотентность
14. **Антидубли для одной вакансии и одного резюме**
   - Given в истории уже есть отклик со статусом `sent` или `queued` на ту же вакансию тем же резюме  
   - When пользователь пытается снова отправить отклик на эту вакансию тем же резюме  
   - Then сервис блокирует отправку и не создаёт повторный отклик

15. **Идемпотентность при повторной кнопке/таймауте**
   - Given пользователь одобрил отправку и сервис начал отправку отклика (`queued`)  
   - When пользователь повторно нажимает “Одобрить и отправить” или происходит повтор запроса из-за сетевого таймаута  
   - Then сервис не создаёт дубль и финальный результат соответствует единственной операции отправки

## Безопасность и соответствие требованиям
16. **Отсутствие хранения пароля HH**
   - Given пользователь использует сервис  
   - When пользователь проходит авторизацию  
   - Then пользователь вводит данные только на стороне HH OAuth, а сервис не запрашивает и не сохраняет пароль/логин HH

17. **Токены не попадают в логи**
   - Given включено стандартное логирование сервиса  
   - When выполняются OAuth-операции и отправка отклика  
   - Then access/refresh токены HH и содержимое черновика письма отсутствуют в логах

18. **Аудит одобрений и отправок**
   - Given пользователь выполняет одобрение и отправку отклика  
   - When операция завершается (успешно или с ошибкой)  
   - Then в аудите есть события “одобрение” и “отправка” с user_id, vacancy_id, resume_id, timestamp и результатом
