# NFR — нефункциональные требования (MVP)

## Security
- **OAuth-only**: авторизация и отправка откликов только через HH OAuth; логин/пароль HH не запрашивать и не хранить.
- **Секреты**: client secret (если используется), ключи шифрования и прочие секреты хранятся только в секрет-хранилище среды (env/secrets manager), не в репозитории.
- **Токены**:
  - access/refresh токены HH хранятся **в зашифрованном виде** (encryption at rest).
  - доступ к токенам — по принципу наименьших привилегий (только сервисный компонент, которому это нужно).
  - токены **никогда не пишутся в логи**.
- **Шифрование**:
  - TLS для всех внешних соединений.
  - шифрование конфиденциальных полей в БД (токены, потенциально `hh_user_id`).
- **Логирование без PII**:
  - запрет логирования содержимого черновика письма, полей резюме, контактных данных.
  - при необходимости диагностики — только технические идентификаторы (user_id, vacancy_id, resume_id), коды ошибок HH.
- **Аудит отправок**: фиксировать событие “одобрение” и “отправка отклика” с user_id, vacancy_id, resume_id, timestamp, результатом.
- **Защита от CSRF/XSS** (если есть веб-интерфейс), безопасные cookies/headers, строгая политика CORS.

## Reliability
- **Очереди**: все сетевые операции к HH API, которые могут занимать время (поиск, отправка отклика), выполняются через очередь/джобы (или эквивалентный механизм фоновых задач) для контроля ретраев и нагрузок.
- **Retries**:
  - ретраи только для транзиентных ошибок (5xx, timeouts, rate limit) с exponential backoff и джиттером.
  - не ретраить “бизнес-ошибки” (например, отклик уже отправлен, нет прав, вакансия закрыта).
- **Idempotency**:
  - отправка отклика идемпотентна на уровне сервиса по ключу `(hh_user_id, vacancy_id, resume_id)`.
  - повторный запрос “отправить” при сетевом таймауте не должен приводить к дублю.
- **Деградация**:
  - при недоступности HH API — понятные сообщения пользователю, сохранение черновиков письма, повторная попытка отправки по запросу пользователя.

## Performance
Планируемый объём (MVP, ориентиры для sizing; значения уточняются по факту):
- **Поиск вакансий**: до 5 000 вакансий/день на всю систему (суммарно по всем пользователям).
- **Генерация черновиков письма**: до 1 000 черновиков/день.
- **Отклики**: до 300 отправленных откликов/день.

Требования:
- Список вакансий по профилю поиска (с ранжированием) отображается пользователю за **≤ 5 секунд** при нормальной доступности HH API (без учёта OAuth).
- Генерация черновика письма за **≤ 10 секунд** в P95 (зависит от провайдера генерации; допускается асинхронный режим со статусом).
- Отправка отклика: пользователь получает подтверждение результата за **≤ 5 секунд** после завершения запроса к HH API; при асинхронной отправке — немедленно показывать статус `queued` и обновлять итог.

## Observability
- **Логи**:
  - структурированные логи (JSON), корреляция по `request_id`/`job_id`.
  - уровни: info/warn/error, без PII и без текстов писем.
- **Метрики** (минимум):
  - количество поисков, найденных вакансий, сгенерированных черновиков письма;
  - количество одобрений и отправленных откликов, доля ошибок отправки;
  - latency внешних вызовов (HH API, генерация письма), rate limits.
- **Алерты**:
  - рост ошибок отправки отклика выше порога;
  - рост 429/5xx от HH API;
  - необычный рост числа отправок/дублей (защита от регресса антидублей).

## Compliance / ToS awareness
- Использовать только разрешённые способы доступа (официальные HH API).
- **Обязательное одобрение** перед отправкой отклика (MVP режим approve_and_send).
- Консервативные лимиты на отправки/поиски и троттлинг, чтобы не выглядеть как бот.
- Явное исключение: автоматический массовый автосенд без подтверждения.

## Data retention
- История откликов и профили поиска: хранить по умолчанию **12 месяцев** (значение конфигурируемое), затем удалять/анонимизировать.
- Черновики письма: хранить **3 месяца** (или до удаления пользователем), затем удалять.
- Аудит событий отправки (без содержимого письма): хранить **12–24 месяца** для разборов инцидентов.
- Удаление аккаунта: по запросу пользователя удалять/анонимизировать все данные, кроме минимально необходимых технических записей, если они требуются законом/политикой (уточняется); токены HH — удалять немедленно.
