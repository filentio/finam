# Scope MVP — рамки первого релиза

## Режимы работы
### MVP режим: approve_and_send
Единственный режим в MVP — **approve_and_send**:
- сервис формирует список вакансий, ранжирует их и создаёт **черновик письма**;
- **отклик** отправляется **только после одобрения** пользователем;
- без одобрения допустимы только “безопасные” действия: поиск, просмотр, ранжирование, генерация и редактирование черновика письма.

### Опционально (позже, не в MVP)
- **draft_only** (флаг): генерировать черновики и сохранять их, но не отправлять отклики из сервиса.
- **auto_send** (флаг): отправлять отклики автоматически по правилам без ручного одобрения.

Важно: режим **auto_send** в MVP **явно запрещён**.

## Что входит в MVP
- **Платформа**: только hh.ru.
- **Авторизация**: только HH OAuth (без хранения пароля).
- **Профиль поиска**:
  - создание/редактирование профиля поиска;
  - фильтры и стоп-листы (компании/ключевые слова);
  - запуск поиска по профилю поиска.
- **Поиск вакансий**:
  - получение вакансий по профилю поиска через HH API;
  - базовая нормализация и сохранение “снимка” вакансий, достаточного для истории и антидублей.
- **Ранжирование вакансий**:
  - rule-based скоринг (совпадение ключевых слов, локация, зарплата, опыт и т. п.);
  - отображение ранжированного списка;
  - простое объяснение ранга (3–5 факторов).
- **Черновик письма**:
  - генерация черновика письма под выбранную вакансию и выбранное резюме пользователя (по `resume_id`);
  - просмотр и редактирование черновика письма пользователем.
- **Отклик**:
  - отправка отклика на вакансию через HH API после одобрения;
  - антидубли на связке `(vacancy_id, resume_id)` для конкретного пользователя;
  - лимиты отправок и quiet hours.
- **История**:
  - история откликов и статусы: `draft`, `approved`, `queued`, `sent`, `failed`;
  - причина ошибки (техническая, без PII) при `failed`.

## Ограничения MVP (явные)
- **Только hh.ru**: любые другие площадки не поддерживаются.
- **Только approve_and_send**: нет автоматической отправки без одобрения.
- **Без сложного ML/embeddings**: ранжирование — эвристики/правила; персонализация минимальная.
- **Без хранения пароля HH**: только OAuth, токены — в защищённом виде.
- **Умеренные лимиты**: консервативные ограничения по отправкам/дню и запросам к HH API.
- **Human-in-the-loop**: обязательный экран предпросмотра/редактирования перед одобрением и отправкой.

## Явно исключить из MVP
- Массовый автосенд без подтверждения (включая расписания/автоправила).
- Интеграции с другими площадками вакансий.
- Сложный ML/embeddings, обучение моделей на данных пользователя.
- Хранение логина/пароля HH, любые механизмы обхода OAuth.
- Скрейпинг HTML/неофициальные методы доступа к данным HH вместо API.
